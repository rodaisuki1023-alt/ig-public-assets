**ファイルをつなげることの影響と対策**

- 構文解析器 acorn（手元に既にあったもの）で、全54スクリプト（外部49、インライン5）を解析しました。
  - 外部49ファイルは、すべて最上位に宣言も `"use strict"` もありませんでした（すべて即時実行関数）。そのため、1ファイルずつ try/catch で包めます。1ファイルの最上位で例外が起きても、止まるのはそのファイルだけです。例外は非同期で投げ直すので、onerror や pageerror には従来どおり届きます。
  - 最上位の宣言があるのはインライン27番（`let items` など）だけで、インラインはつなげません。
  - `document.currentScript` はどこでも使われていません。最上位の let/const/class の重複もありません。
  - これらの条件を満たさないファイルがあると、ビルドは止まります（自動で失敗する安全装置）。
- キャッシュの更新
  - チャンクの名前に内容のハッシュを付けます。
  - service-worker.js の事前キャッシュに、チャンクと `index-src.html` を加えます。`CACHE_VERSION` にも方式名とハッシュを付けます。
- 読み込みに失敗したとき
  - チャンクの読み込みに失敗すると、元の構成（`index-src.html`、同じ保存キー）へ1回だけ切り替えます。
  - チャンク3を消したビルドで確認しました。`index-src.html` に切り替わり、商品30件がそのまま残り、ストック一覧も表示されました。
- 対応表：`bundle-map.json` に、チャンクとファイルの対応・行の範囲・sha256 を書き出します。
- OCRがOFFのときは、OCRの4ファイルを読み込みません（従来どおり）。OCRがONのときの順序も、E2Eで確認しました。
- 本番に採用するには、配信の手順（CI/CD）を変える必要があります。**採用は別の明示承認が必要**です。今回は試作と比較だけです。

- **画面外のカードを省く**：`#stockList` のカードに `content-visibility:auto` を付けました。

- **display.js の以前からの不具合**

  - CSSをまとめたバンドルで、テストが失敗したことから見つけ、修正しました。
- **試験基盤**：エミュレーターの keep-alive を65秒に延ばし、接続の異常を記録するようにしました（`socket hang up` の再発に備えたもの。原因は未証明）。
