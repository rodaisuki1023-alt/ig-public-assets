## 1. 有料機能の価値の整理

原則として、**記録して見る**機能は無料で完結させます。有料にするのは、**手間なく続けるため**の機能、つまり通知・自動化・容量・保管です。

| 候補 | 誰の、どの手間を減らすか | 無料との境界 | 運営側の追加原価 | 状態 |
|---|---|---|---|---|
| 切れそうな物のお知らせ | アプリを開かなくても、補充の時期に気づける | 無料：アプリ内の「見積 あと◯日」とホームの確認。有料：プッシュ通知・家族への通知 | 通知の配信（Web Push は無料枠の範囲で済む見込み）＋送信を判断する処理 | 未提供（試用の通知画面だけ。実際には送信しない） |
| 曜日別の準備の自動表示（高度） | 曜日・行事・子どもごとの持ち物が、前日の夜に自動でそろう | 無料：曜日・行事・子どもの持ち物の登録とチェック。有料：前日の自動表示、不足を自動で買い物リストへ提案 | 端末内の処理が中心で、原価はほぼない | 未提供 |
| 共有写真の追加枠（5→20枚） | 家族が「どの商品か」を写真で迷わない | 無料：共有写真5枚と、端末内の写真は無制限 | 保存容量（Supabase Storage）。原価が最も読みやすい | 上限の仕組みは実装済み。有料枠は未提供 |
| 自動バックアップ履歴 | 機種変更や誤操作から戻せる | 無料：手動のバックアップと復元 | 保存容量と保持期間 | 未提供 |
| 家族の人数（2→6人） | 祖父母やシッターも共有できる | 無料：2人 | アカウント数（小さい） | 上限の定義だけあり（`seats`） |

- 優先順位の案は、**お知らせ → 写真枠 → 自動バックアップ → 準備の自動化**です。理由は、継続して払う理由が最もはっきりしていて、原価が読みやすいことです。
- 需要は未検証です（`atokore-v51-validation-plan-20261125.md` の14日目の聞き取りが未実施）。

## 3. 規約類の必要項目と原案（要専門家確認）

`［ ］` は、オーナーが決める・記入する箇所です。

### 3-1. 利用規約（原案）

1. **適用**：本規約は、［運営者名］（以下「運営者」）が提供する「あとこれ」（以下「本サービス」）の利用に適用されます。
2. **アカウントと家族共有**：家族共有を使う場合、招待した人とされた人は、世帯のデータを共同で使います。世帯の作成者は、メンバーを外すことができます。
3. **料金**：無料プランは無料です。有料プランの内容と料金は、申込画面と特定商取引法に基づく表記で示します。価格は消費税込みで表示します。
4. **有料プランの更新と解約**：有料プランは、解約しない限り、同じ期間で自動的に更新されます。解約は［マイページ／決済事業者の管理画面］からいつでもできます。解約しても、その期間の終わりまでは有料プランを使えます。
5. **プランの終了時の扱い**：有料プランが終わっても、保存済みのデータと写真は削除しません。無料プランの上限を超える新しい追加だけを止めます。
6. **返金**：［法令で必要な場合を除き、日割りの返金は行いません／運営者の判断で返金できる場合］
7. **禁止事項**：法令違反、他人へのなりすまし、不正なアクセス、サービスへの過度な負荷、ほかの利用者の情報を不正に取得すること。
8. **サービスの変更・停止**：保守や障害のとき、運営者はサービスを一時的に止めることがあります。有料機能を廃止する場合は、［30日］前までに知らせます。
9. **免責**：在庫数や補充の見積もりは目安です。実際の在庫や購入の判断は利用者が行うものとします。［消費者契約法の範囲で責任を制限する条項：要専門家確認］
10. **データの扱い**：プライバシーポリシーに従います。
11. **規約の変更**：変更するときは、効力が生じる日と内容を事前に知らせます。
12. **準拠法・管轄**：日本法に従います。管轄は［運営者所在地の地方裁判所］とします。

## 4. 決済・解約・プラン変更の設計（未実装・鍵の発行なし）

- **方式（案）**：Stripe Checkout と Customer Portal。Webアプリなので、アプリストアの課金は使いません。
  - 固定費は0円で、決済手数料だけがかかります（日本の国内カードは3.6%。`phase-d` 調査時点の値で、販売開始時に再確認する）。
  - インボイス（適格請求書）は、運営者が登録しているかどうかで扱いが変わります（要確認）。
- **流れ**：
  1. マイページ → 最終確認画面 → Stripe Checkout
  2. Webhook（Supabase Edge Function）が署名を検証し、イベントIDを1回だけ適用します。
  3. `hh_entitlements` の `plan` と `premium_until` を更新します。
  4. 端末は `fromServer()` で表示を変えます。不明な状態は無料として表示します。
- **契約の単位**：世帯（household）ごとに1契約です。決済した人が世帯を抜けても、期間中は世帯の有料プランを維持します（方針は要確認）。

| 出来事 | サーバーの扱い | 画面 |
|---|---|---|
| 新規申込み | 支払いの完了イベントを受けて、`premium_until` を期間の終わりに設定 | 「有料プランが有効です（◯月◯日まで自動更新）」 |
| 更新の成功 | `premium_until` を延長 | 変化なし |
| 更新の失敗 | 猶予を［7日］置き、そのあいだは有料のまま。猶予が過ぎたら無料に戻す | 支払い方法の確認を1行で案内 |
| 解約の予約 | 期間の終わりまでは有料のまま。自動更新を止めた印を付ける | 「◯月◯日まで有料プラン。その後は無料プランに戻ります」 |
| 期限切れ | 無料に戻す。**データ・写真は削除しない**。上限を超える新しい追加だけを止める | 写真枠「n/5枚・上限を超えています」（実装済みの表示） |
| 月額から年額への変更 | Customer Portal で変更。日割りの差額は Stripe の按分で計算 | 次回の請求額を表示 |
| 年額から月額への変更 | 期間の終わりに切り替える（途中での返金はしない） | 切り替わる日を表示 |
| 返金 | 管理画面で手動対応し、Webhook で `premium_until` を戻す | — |
| 同じイベントの再送、順番の入れ替わり | イベントIDを1回だけ適用し、最新の状態に揃える | — |

- **試験の方針**：テストモードの Webhook を合成データで試します（実決済はしません）。
  - 同じイベントの重複、順番の入れ替わり、失効したときの写真の上限を確認します。
  - 鍵の発行・設定・有効化は、オーナーの承認を得てから行います。
