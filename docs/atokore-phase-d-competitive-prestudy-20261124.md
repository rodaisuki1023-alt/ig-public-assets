## 無料/有料の仮説（未決定）

- **無料維持を優先**：在庫・買い物、2人の家族共有、在庫非連動の基本持ち物チェックリスト、端末内OCR（品質不十分な間は非表示）、「買った→ストック反映」。
- **有料候補の優先順**：
  1. 複数児・複数園・保護者の**繰り返し準備と役割分担**（毎週使う価値。基本セットは無料で残す）。
  2. **安全な自動バックアップ/端末引継ぎ履歴**（費用/暗号化/プライバシーを先に実証）。
  3. **消耗品の補充予測/実績に基づく提案**（少ないデータで過信しない。実測精度がなければ見送り）。
- **保留**：サーバーOCR、AIによる無確認での在庫加算、強制サブスク、バーコード/音声の全機能模倣。クラウドOCRは容量と個人情報を増やすため安全ゲート・需要根拠・単位経済性が揃うまで導入しない。
- プレミアム6人上限は競合の買っとく？最大10人より少ないため、**人数だけで有料に誘導しない**。

## 決済の最低限の算術（市場予測ではない）

Stripe日本向け標準カード決済は通常 **3.6%**（https://stripe.com/jp/pricing）。月398円で1決済あたり基本決済手数料だけの理論値は約14.3円。税務、返金、Billing追加費用、各種カード/決済方法別費用、セキュリティとサポート運営費は別途発生する可能性があり、**約383.7円は利益額ではない**。100世帯加入なら売上39,800円/月の仮想値であり、需要・加入率・継続を確認していない。

ネイティブiOS/Androidストア販売の契約・IAP/外部決済、Apple Developer Programの年会費などはPWAと別。アプリ内課金を実装済みと見せない。Apple日本のストア決済ルールは変更するため、着手前に公式確認（https://developer.apple.com/jp/support/payment-options-on-the-app-store-in-japan）。

## 広告/SNS/DMなし・iPhone完結の獲得仮説

1. 「保育園 持ち物 忘れ物」「おむつ ストック 共有」「赤ちゃん 買い物リスト 家族共有」等、**困りごとの具体的検索意図**へLP＋短い説明記事を設計。実行前にGSC/Google Trendsでキーワード需要と競合を確かめ、順位やCV数は推測しない。
2. アプリ内の招待リンクを家族が**自発的**に送る自然な導線。勧誘DMやSNS投稿は行わない。本人の知人への押し売りも前提にしない。
3. インデックス可能なヘルプ（使い方/安全なバックアップ/機種変更/無料範囲/保育園リスト）を同一ドメインに揃える。ドキュメント公開・外部サイト登録は別承認。
4. 計測は最小限・匿名/端末内を優先。Google Analytics等の外部計測を無断導入しない。家族や子供の実名、レシート本文をKPI用に送らない。
