# あとこれ｜iPhoneでの安全なレビュー用ビルド（未公開）

対象：#96 Phase Aの試用前検証 / #102の家族共有リスク。通常のv19試用版や公開サイトは変更しない。

## 目的
現行v19の標準`build-preview.py`では、旧`family.js`を無効にしても、新しい`household-config-v37.js`が実際の試用用Supabaseを指している。そのため、すでに認証状態を持つ端末では家族共有同期が発生しうる。実iPhone確認のために、**ローカル保存だけを使い家族共有のAPIを初期状態から無効にする**別のビルド方法を用意する。

## 生成手順（開発環境でのみ利用）
```sh
python3 -I scripts/atokore/build-local-review.py atokore-live-v125 _local_review 19
```

生成物は以下を満たす：
- 正式のプレビュービルダーと同じ通常版/試用版保存キー分離を実施。
- 旧family.jsの無効化に加え、アクティブな家族共有設定`ATOKORE_HOUSEHOLD_CONFIG`を`null`に固定。アプリの`household-sync-v37.js`は設定検証で実行を停止。
- 公開の試用Supabase URLを含まず、Google家族共有ログインもできない。UIバッジに「ローカル確認用・家族共有無効」と明示する。
- OCRなどの外部静的アセットへのアクセスまで禁止するビルドではない。**家族共有のDB接続を止める**ための限定措置。

## 絶対条件
- **このPRはビルドスクリプトとCIだけ。Pages、Netlify、Vercelへ公開しない**。
- 現時点で本機能の家族共有の実動作を証明するものではない。DBのRLS、招待、共有同期、権限失効などは別のテストと承認が必要。
- iPhone Safariでレビューするために後日限定プレビューデプロイが必要となる場合は、**公開先・保存キー・URL・ロールバック・本人承認**を確認して別のPRで行う。試用通常版の既存利用者と保存データを上書きしない。
- 同一オリジンの既存サイトからのLocalStorage読取が理論上可能なので、**独立したオリジン／非ログインの合成ユーザーデータ**で実機評価するのが理想。機密の家族データを使わない。
