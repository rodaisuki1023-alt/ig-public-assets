# あとこれ v51：無料運営・収益化の検証準備（2026-11-25）

**この資料は準備だけです。**
- 販売、通知の送信、決済の有効化、公開、noindexの解除は行っていません。
- 金額はすべて検証のための仮説です。
- 追加の固定費は0円です。

## 1. 先に確かめる価値
Workの方針に沿って、次の流れを最初に検証します。

**園の準備で不足に気づく → 家族の買い物に渡す → 買って補充 → 次の準備では聞かれない**

統合候補には、この流れの部品が揃っています。
- 持ち物セット：曜日・行事・子ども・園の別
- 不足のまとめ：サイズ候補を選べる
- 担当と返信：草案。既定は無効
- 購入から推定への反映：家族の同時購入にも対応

## 2. 10〜20世帯で14日間の検証（設計）

| 項目 | 内容 |
|---|---|
| 対象 | 0〜3歳の子がいて、保育園か幼稚園に通う世帯。iPhone利用。家族の2人以上が参加 |
| 期間 | 14日。1日目に登録、2〜14日目は普段どおり使う |
| 環境 | 認証付きの試用URL（新規デプロイは別承認）。合成データではなく本人のデータを使うため、同意書と削除手順を事前に用意する |
| 主な指標 | 7日目と14日目に使い続けている割合／園の準備から不足を見つけた回数／買い物リストへの引き継ぎ回数／買った後に推定が正しかった割合（本人の自己申告）／家族の担当に返信した割合 |
| 時間の記録 | 初回登録にかかった時間は、**本人の実操作を画面録画で測る**。自動テストの所要時間は、利用者の所要時間として扱わない |
| 価格への関心 | 14日目に、月298円と月398円のどちらか（または「払わない」）を聞く。購入ボタンは置かず、課金もしない |
| 判断の基準（仮） | 14日目に使い続けている世帯が50％以上で、引き継ぎが1世帯あたり週1回以上なら、有料化の検証へ進む |
| 中止の条件 | データの消失・誤った加算・共有の失敗が1件でもあれば、その機能を止めて原因を調べる |

## 3. 無料・有料の境界（仮説）
- **無料のまま**：在庫、買い物、持ち物チェック、端末内の写真、家族共有の基本、共有写真5枚。
- **有料の候補**：共有写真20枚、消費予測と補充日の通知、担当と返信の通知、詳しい履歴。
- 権限の表示は `entitlements-v51.js` で行います。分からないときは無料として扱い、提供していない有料機能は「検討中・未提供」と表示します。
- 写真の枚数だけを課金の柱にはしません。時間が短くなること（予測・通知・家族の引き継ぎ）を価値にします。

## 4. 通知（試作・送信なし）
`proposals/notify-policy-v51.cjs` で、次を決めています。
- **送らない時間と回数**：21〜7時は送らず朝に回す。1日3件まで。間隔は30分以上空ける。重なったものは1件にまとめる。
- **送らないもの**：同じものの重複、本人自身の操作、全体でオフにしている人、36時間を超えた古いもの、すでに解決したもの（判定が失敗したときも送らない）。
- **表示の配慮**：ロック画面に商品名は出しません。
- 実際に送るには、Web Pushの承認とiPhoneでの確認が必要です。

## 5. 無料枠の監視（試作）
`proposals/usage-monitor-v51.cjs` の内容です。
- 合成データで、使用率50/70/80/90％の段階と月末の予測を出します。
- 取得できない値は0として扱わず、「不明」とします。
- 実際の使用量は、Workの判断どおり既存のUsage画面で確認します（トークンは当面不要）。

## 6. 写真圧縮の実測（合成画像）
`scripts/atokore/measure-photo-compression.cjs` で、アプリの圧縮処理（`AtokoreProductPhotos.compress`）を直接測りました。Chromiumを使用しています。

- **対象**：合成画像20枚。4032×3024、3024×4032、1920×1080、1080×1080のPNG、640×480 を各4枚。
- **結果**：出力は平均8,871バイト、中央値8,101バイト、最大10,669バイトです（上限81,920バイト、256×256のJPEG）。
- **未確認**：実際の写真とiPhone Safariでのサイズは未測定です。HEICの読み込みも実機での確認が必要です。

## 7. 無料ツールから本体への誘導・SEO公開前チェック
- **今の状態**
  - `noindex` のままです。
  - 本体のURLがまだないため、ツールの最後に「公開準備中」と書くだけにしています。
  - 「無料・ログイン不要」と明記しています。
- **公開するときの条件**（すべて別承認）
  1. 本体の正式なURLと、認証のない公開ページが用意できている。
  2. canonical URL、OGP、構造化データ（FAQのみ）を確認する。
  3. 計算式と注意書き（体重・月齢による個人差、医療的な判断はしない）を専門家に確認してもらう。
  4. 誘導先を、結果のすぐ下に置く（その場で申し込ませず、「在庫を管理する」という文脈で）。
  5. noindexの解除とサイトマップへの登録。
  6. Search Consoleで、表示されているか・クリックの計測を確認する。
