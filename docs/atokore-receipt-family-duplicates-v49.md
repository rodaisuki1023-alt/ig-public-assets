# あとこれ v49：家族間でのレシート二重取り込みの警告（隔離環境で検証済み・実DB未適用）

確認日：2026-11-02（第2回再監査の対応を反映）。**実際の Supabase（試用版・本番とも）には適用していません。** 適用には事前の承認が必要です。

この仕組みは**確定前の警告**です。二重取り込みを完全に防ぐものではありません。在庫の保存そのもの（確認画面の最後のボタン）は別の処理で、この仕組みが保存をやり直したり、取り消したり、統合したりすることはありません。

## 何をするか・何をしないか

| 状況 | 判定のもと | 結果 | 範囲と限界 |
|---|---|---|---|
| 同じ写真をもう一度取り込む（同じ端末） | 写真データのハッシュ（v38からの端末内の記録）＋共有サーバーの記録 | 警告。進めるかは本人が選ぶ | 端末内：常に働く。家族の端末：共有中・ログイン中・サーバー対応済み・通信できるとき |
| 家族の1人が確定した後、もう1人が同じレシートを取り込む | 店（インボイス登録番号か電話）・日付・時刻・合計・レシート番号から作る指紋 | 確定前に「○○さんが取り込み済み」と表示。キャンセルすれば何も追加しない | 指紋の項目が読めたときだけ |
| 2人が同時に取り込む | 共有サーバーの予約（主キーで一意。同時でも予約できるのは1人） | 後の人に「○○さんが取り込み中」と表示 | 予約は確認画面へ進む時点。本物の PostgreSQL での同時実行は未検証 |
| 30分以上確定しない予約 | 共有サーバーの記録 | 引き継ぐ前に「○○さんが取り込みを始めましたが、確定したかは分かりません」と表示し、本人が選ぶ。キャンセルすると引き継いだ予約を解除 | 前の人が実際に保存したかはサーバーには分からない |
| 撮り直した同じレシート | 指紋（写真が違っても同じ） | 警告 | 指紋の項目が同じように読めた場合だけ |
| 別の日に同じ商品を買ったレシート | 日付・時刻・合計が違う → 指紋が違う | 警告しない | — |
| 確認できなかったとき | 理由を区別して表示 | 下の表 | 在庫は自動で変更しない |
| 保存は成功したが、記録（予約の確定）に失敗 | 応答 `{ok:false}`・通信障害・ログイン切れ・世帯の切り替え | **記録済みとは扱わず**、予約した世帯・利用者にひも付けて確認待ちに入れる。保存はやり直さない | 次にレシートの画面を開いたとき（同じ世帯・同じ利用者のときだけ）に確認する |
| 予約を家族に引き継がれた後で保存した | 自分の確定がサーバーに拒否される（`{ok:false}`） | 確認待ちに入れ、照合して「○○さんが取り込み始めていました（確定したかは分かりません）」と知らせる | 在庫は自動では変更しない |
| 取り込みの途中で世帯を切り替えた・ログアウトした | 予約した世帯・利用者（scope） | 新しい世帯には送らない。元の世帯・利用者の確認待ちとして残す | 元の世帯に戻らない限り確認されない |

### 確認できなかったときの表示（理由ごと）

| 理由 | 表示 | あとで確認するか |
|---|---|---|
| 通信できない | 「通信が戻ってから次にレシートの画面を開いたときに確認します」 | する（同じ世帯・同じ利用者のとき） |
| ログイン切れ・未ログイン | 「共有のログインが切れています。ログインし直すと確認します」 | ログインし直した後にする |
| 共有サーバーが未対応（関数がない＝この変更が未適用） | 「共有サーバーがこの確認にまだ対応していません。端末内の確認だけを行いました」 | 約束しない |
| 世帯から外れている | 「共有している世帯から外れています」 | しない |
| その他 | 「原因は不明です」 | 約束しない |

**限界：**
- 店・日付・時刻・合計／レシート番号が読めないレシートでは指紋を作れず、家族間の確認はできません（端末内の警告だけ）。
- 撮り直しで日付・時刻・合計を読み違えると、別のレシートとして扱われます。
- オフライン後の照合は**知らせるだけ**です。二重に加算された在庫は本人が直す必要があります。
- 「別の買い物として取り込む」を選んだ場合は、本人の判断を優先して追加します。
- **端末内の対策だけでは、家族間の対策が完了したとは言えません。** 家族間の確認には、下のサーバー側の変更が実DBに適用されている必要があります。

## サーバー側の変更（`supabase/migrations/20261101120000_atokore_receipt_imports.sql`）

- **追加のみです。** テーブル1つ（`atokore_private.receipt_imports`）と関数2つ（`hh_receipt_claim`・`hh_receipt_finish`）を追加します。既存のテーブル・行・関数は変更しません。
- 第2回再監査で、引き継ぎの応答に前の人の名前と時刻（`who`・`at`）を加えました。このマイグレーションはこのPRで新しく追加したもので、どの環境にも適用していないため、ファイル自体を更新しています。
- **保存するのは指紋（SHA-256）・状態・取り込んだ人・時刻だけです。** 商品・金額・会員番号・決済情報は送りません。
- 400日より古い記録は自動で消します。消えるのはその世帯の記録だけです。
- 権限：`authenticated` だけが実行できます。世帯の外の人は `not_member` になります。
