# v46 フォローアップ修正報告

対象は `/preview-baby-v19/`。最新main `2257fa3bd69c2b349786e85201498e96ac4c6bad` と固定公開元 `ba867982697099c7aaeccac3961b2c432b909047` を確認し、その公開元から専用ブランチを作成。保存キーはv19のまま維持。数量仕様や保管場所・カテゴリ・メーカー表示には変更を加えない。

## 1. レシートの購入日

- **修正内容**：日付のないレシートは、UTC日付を返す既存today()の代わりに端末のローカル年月日で購入日を補完。印字された購入日と、利用者が編集した日付は引き続き優先。過去の保存データは書き換えない。
- **変更ファイル**：`atokore-live-v125/common-v45.js`、`receipt.js`。
- **修正前**：v45をJST 2026/10/25 00:01に固定して日付なしの文字列を解析すると、購入日が2026/10/24になることを再現。
- **検証手順と結果**：PlaywrightのタイムゾーンをAsia/Tokyo、時計を2026/10/24 23:59、10/25 00:01、08:59、23:59に固定。卵1商品の日付なしレシートを解析→確認→保存。全ケースでJST当日の購入日になり、消費予測の根拠に同じ日付が表示。他商品の既存購入日は不変。別途2026/10/20印字のレシートはその日付を維持。新規テスト5件成功。
- **未対応事項**：iPhoneの実クリップボードから貼り付けた際の改行保持は未検証。この修正で実機貼り付けが直ったとは扱わない。端末のタイムゾーン設定を使用する。

## 2. トーストと取り消し案内

- **修正内容**：クイック追加と通常操作のトーストを共通管理し、新しい通知で古い通知を非表示にする。1.6〜2.2秒で自動終了。取り消しバー表示時は直前の通知を隠す。別の通知が必要な場合はバーの上に置く。画面遷移イベントで取り消しバーと対象コールバックを破棄。同じ画面の「買った」取り消しは維持。
- **変更ファイル**：`common-v45.js`、`stability.js`、`quick-add.js`、`polish-v44.js`。
- **修正前**：v45で追加予定を取り消した通知と通常操作通知が同時に残ること、数量変更後にホームへ移動しても取り消しバーが残ることを再現。
- **検証手順と結果**：追加予定全取り消し→別通知→旧通知非表示→時間経過で消去。「買った」→新しい通知の領域が取り消しバーと交差しないこと→取り消しで買い物を復元。数量変更と購入の両方でホームへ移動するとバーが消え、戻っても再表示されず、確定した購入状態を維持。新規テスト2件成功。
- **未対応事項**：なし。画面内の保存エラーなど、常設の説明・エラー表示は一時通知として消さない。

## 3. 買う数量の説明と買い物削除

- **修正内容**：ストックからは従来どおり各商品1点を買い物に追加する。ストック側に「各商品1点ずつ追加」「ストックの数量は減りません」、買い物の商品行に「買う数量（ストックからは1点ずつ追加）」と表示。個別・一括削除をストックと同じアプリ内確認へ統一。キャンセルは保存データを変えず、確定時だけ削除・保存・通知。保存失敗時は既存のロールバックを維持。
- **変更ファイル**：`stability.js`、`index.html`。
- **修正前**：v45では数量の説明がなく、個別削除は確認なし。数量説明の欠如を修正前ブラウザテストで確認。
- **検証手順と結果**：ストック数量2の商品から買い物へ追加→買う数量1・ストック数量2を維持し説明を確認。ゴミ箱→確認表示→キャンセルで不変→再度削除し確定→リロード後も削除を保持、他の買い物とストック全項目は不変。新規テスト1件成功。「買った」・取り消しは項目2および既存の購入テストで再確認。
- **未対応事項**：数量仕様は変更していない。保管場所「その他」やメーカー表示など、依頼範囲外の改善は含めない。
