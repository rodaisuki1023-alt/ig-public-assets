# あとこれ v42：招待リンク・Googleなし参加・機種変更

## 方針
作成者はGoogleなどの永続アカウント。招待された人は名前とコードだけで参加でき、端末内に匿名認証セッションを保存する。ログインの省略であり、共有DBを公開することではない。招待を受けた人以外は読み書きできない。通常版と既存の共有データは変更しない。

## 招待を受ける人
1. Safariなどで招待リンクを開く。コードは画面へ入る。開いただけでは参加も在庫変更もしない。
2. 表示名を入れ「Googleなしで共有に参加する」を押す。必要な認証情報だけを端末内に保存する。
3. 端末内に在庫がある場合は、共有のデータを使うか、端末の商品も加えるか選ぶ。上書き前に控えを保存する。
4. 同じブラウザからの再利用では保存したセッションを更新し、アプリを開いたとき・オンライン復帰時に同期する。閉じている間の即時同期は保証しない。

Googleで参加したい人には別ボタンを表示する。後から匿名アカウントをGoogleへ連携する処理は、この変更には含めない。匿名参加後に単にGoogleログインするだけで、元の参加者として復旧できるとは案内しない。

## Googleで参加した人の機種変更
1. 旧端末の家族共有で「家族と共有済み」を確認する。
2. 新端末で同じ試用版URLを開く。
3. マイページ → 家族共有 → 同じGoogleアカウントでログイン。
4. 既存の世帯を読み出す。新しい世帯は作らない。
5. 新端末に在庫がある場合は内容を確認し「共有のデータを使う」を選ぶ（空なら共有データを受信）。

復旧対象：共有先へ送信済みの在庫・買い物リスト・いつものリスト。
対象外：写真、未送信の変更、端末内だけの控え、表示設定。Googleは本人確認であり、Google Driveへ在庫や写真を保存する機能ではない。共有を始めていないローカル在庫は、Googleログインだけでバックアップされない。

## Googleなしで参加した人の機種変更
旧端末を使えず、ブラウザの保存情報も失った場合：作成者の家族共有で該当メンバーを「外して再招待」→新しい招待コードを発行→新端末で参加する。以前の端末は以後共有へアクセスできない。共有済みデータは消さない。未送信の内容・旧端末の写真は復元できない。外す対象は本人が確認し、削除や再招待を自動では行わない。

## 外部設定と公開条件
専用Supabaseで匿名認証を有効にする必要がある。ユーザーが参加ボタンを押したときだけ匿名アカウントを作る。既存の招待コード期限・使い切り・失敗回数制限・世帯メンバーの権限チェックを維持。匿名ユーザーはサーバー側で新しい世帯の作成を拒否する。

実サービスの匿名認証が有効、所有者ガード適用済み、ソースCI成功、限定試験で接続を確認するまでv42を公開しない。v41のGoogle経路は維持する。無料枠を使い、有料API・決済・写真のクラウド共有は追加しない。

## 検証の区別
模擬Authと実SQLによる複数ブラウザの検証、Hosted DBのトランザクション内検証、実Supabase Authの匿名認証、実スマホ2台を分けて記録する。Googleの実ログインや実機2台で成功したとは模擬試験から言わない。
