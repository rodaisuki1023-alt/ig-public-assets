# Muse修正指示への対応（機能更新v45）

対象：`preview-baby-v19/`。v19は公開先・保存領域の識別番号、v45は機能更新番号。

最新のmain `5fab3dcc735c8057fdb3d2315646551b91254c68` と、そこで固定している公開元 `276a3077e43afb1b472e8b5cc6f1ce5b5200907f` を確認。この公開元から専用ブランチを作成した。既存の試用版保存キーを維持する。通常版のソースと他の作業ブランチは変更対象外。

## P0-1 ストックの削除

- **修正前**：標準confirmを抑止したブラウザ条件で、一括・詳細削除が中断。実機評価の原因を完全に同定したものではないが、同じ無反応になる経路を再現した。
- **修正内容**：両経路をアプリ内の確認画面へ統一。対象名を示し「削除する」で確定する。保存成功後に選択状態・一覧・ホームを更新しトーストを出す。保存失敗時は既存のロールバック処理を利用し、成功表示を出さない。キャンセルで詳細を維持する。
- **変更ファイル**：`common-v45.js`、`stability.js`、`atokore-redesign.js`、`muse-v45.css`。
- **検証手順と結果**：標準confirmが常にfalseになる条件で、一括選択→削除→アプリ内で確定、詳細→削除→確定を操作。対象が保存データ・一覧・ホームから消え、再読み込み後も戻らず、対象外の商品全項目が一致。キャンセル時は保存データが一致。新規ブラウザテストに合格。
- **未対応事項**：削除の「元に戻す」は追加していない（受け入れ条件上は任意）。iPhone実機の同じブラウザ内での再確認は利用者確認事項。

## P0-2 期限表示

- **修正前**：ホームは暦日差、ストックは期限日の23:59:59からの切り上げで、同日差が1日ずれた。詳細には期限表示自体がなかった。
- **修正内容**：共通の暦日計算に統一。期限当日0日、翌日-1日。すべての画面で「あと2日（10/26まで）」「今日まで（10/24まで）」「期限を1日超過（10/23まで）」の同じ表記を使う。期限なしはバッジを出さず詳細に明記。
- **変更ファイル**：`common-v45.js`、`index.html`、`home-v43.js`、`stability.js`、`atokore-redesign.js`。
- **検証手順と結果**：時計を2026/10/24に固定し、10/26・当日・前日・期限なしをホーム→ストック→詳細で照合。全画面で一致。時刻0/12/23時・年越し・不正日付を単体テストで確認。
- **未対応事項**：なし。端末のローカル日付を基準とする。

## P1-3 「買った」

- **修正前**：行のチェックは一括選択用で、購入操作は「在庫へ反映」など複数の用語だった。
- **修正内容**：商品行に大きな「✓ 買った」を設置。押した時点で直ちに数量をストックに加算し、買い物リストから消す。既存の「元に戻す」を維持。一括操作のチェックは「一括選択」と明記。注記・操作履歴も「買った」に統一。
- **変更ファイル**：`stability.js`、`baby-flow-v17.js`、`polish-v44.js`、`home-v43.js`、`history.js`、`household-sync-v37.js`、`muse-v45.css`。
- **検証手順と結果**：「買った」を1回押し、買い物から消えストックに1回だけ加算→「元に戻す」で復元。区別したアクセシブル名と44px以上の操作領域を確認。新規ブラウザテストに合格。
- **未対応事項**：保存済みの過去の履歴文言は書き換えない。

## P1-4 追加予定の全取り消し

- **修正前**：標準confirmを抑止すると全取り消しが中断した。
- **修正内容**：アプリ内確認で「全部取り消す」を押すと追加予定を空にし、商品選択画面に戻りトーストを表示。保存済みデータは変更しない。
- **変更ファイル**：`quick-add.js`、`common-v45.js`。
- **検証手順と結果**：追加予定を入れる→全取り消し→確定、確認画面が閉じ、トレイが空、保存データは実行前と一致。標準confirmが抑止されても成功。新規ブラウザテストに合格。
- **未対応事項**：実機評価のブラウザ内部で標準ダイアログが抑止されたかどうかは未確認。

## P1-5 写真なし一覧の詳細

- **修正前**：最新の公開元を使ったこちらのChromiumでは、行名タップ・キーボードで詳細が開き、無反応は再現しなかった。
- **修正内容**：カード・写真なし一覧とも、行のクリックハンドラが直接詳細表示を呼ぶ形に統一。一括選択中は行選択、数量ボタンは数量変更だけを行う。
- **変更ファイル**：`stability.js`、`atokore-redesign.js`。
- **検証手順と結果**：写真なし一覧で商品名タップ・Enterで詳細を開く。＋では詳細を開かず数量だけ変わる。新規ブラウザテストに合格。
- **未対応事項**：Museの評価端末での再確認。再現していない現象を「同じ原因を修正済み」とは扱わない。

## P2-6 名称・用語

- **修正内容**：「いつものリスト」に統一。ホームは期限対象も含むため「補充・期限の確認」とし、編集画面からの説明も合わせた。補充目安の説明を追加。追加画面の見出しは保存先に追随。「その他」は衣類・園用品・家電・防災を含むため「衣類・園用品ほか」へ変更。キユーピーは追加では「生産終了品を登録する」、ストックでは「（生産終了）」付きで選択可能。公開先v19／機能更新v45の関係をマイページに明記。
- **変更ファイル**：`baby-flow-v17.js`、`data-safety-v19.js`、`quick-add.js`、`edit-after-add.js`、`home-v43.js`、`insights-v45.js`、`history.js`。
- **検証手順と結果**：保存先の両方向切替で見出し追随、離乳食両画面でキユーピーの導線、買い物画面の名称、マイページの更新番号を新規ブラウザテストで確認。
- **未対応事項**：保存された利用者の商品カテゴリ・リスト名・過去の履歴は自動改名しない。

## P2-7 名前と内容

- **修正内容**：消費予測は根拠のない％をなくし「消費予測（補充の目安）」として残数・補充目安・記録済み購入日を表示。在庫0を最優先にする。消費ペース未計測を明記。「収納QR」は既存の場所別一覧を保ったまま「保管場所別ストック」に改名。「節約レポート」は「価格記録レポート」にし、商品別の価格×数量と合算根拠を表示。数量0は価格×0で計算。古い購入合計だけの記録は残量に連動しない参考額と区別。節約額と称しない。
- **変更ファイル**：`insights-v45.js`、`edit-after-add.js`。
- **検証手順と結果**：0個・2個の商品の並びと根拠、198円×0=0円／100円×2=200円の内訳、場所別一覧の名称と内容をブラウザテストで確認。計算の単体テストに合格。
- **未対応事項**：実測の消費ペースからの期限予測、QR生成・スキャン、実際の節約額の算定は追加していない。現在の内容に合わせた表示改善で対応。

## P3-8 細部

- **修正内容**：空状態に「商品を追加する」を追加し、離乳食フィルターからは離乳食の追加画面へつなぐ。レシート貼付に1行1商品の入力例と改行案内、CR・Unicode改行の対応を追加。表示設定の見本は「サンプル」と明記。ストック・買い物の数量操作を44px以上にし、ストックの＋／－は背景と枠を明確化。
- **変更ファイル**：`insights-v45.js`、`receipt.js`、`display.js`、`muse-v45.css`。
- **検証手順と結果**：離乳食の空状態→追加導線、改行付き貼付で2商品を解析、サンプル表記、320/390/430pxで数量ボタンの領域と横はみ出しをブラウザテストで確認。15件の新規テストは全件合格。
- **未対応事項**：通常のLF改行は既存経路でも保持されており、Museの実機で改行が消えた原因は未同定。アプリが受け取る前に消えた区切りを自動推測して商品を分割する処理は追加しない。実物レシートOCR精度の実機評価は別途必要。
