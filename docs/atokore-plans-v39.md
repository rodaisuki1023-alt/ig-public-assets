# あとこれ 無料／有料の範囲とサブスク準備（v39）

> **準備だけです。** 支払いの仕組みは接続していません。購入ボタンもありません。課金・販売も始めていません。
> 有料の目玉になる機能（サーバーでのレシート読み取り・自動バックアップ）はまだ作っていません。販売はそれができてからです。

## 1. 方針
- **契約は世帯単位**：夫婦それぞれに請求しません。世帯の全員が同じプランを使います。
- **解約・期限切れでもデータは消しません**：在庫・写真・履歴・メンバーはそのまま残ります。閲覧・書き出し・無料の範囲での利用を続けられます。
- **画面の表示や端末の値は信用しません**：プランはサーバーの表にだけあります。利用者の端末からは変更できません（テストで確認済み）。
- **費用がわからないものを「無制限」と約束しません**：上限を設けるのは、サーバー側で実際にお金がかかる機能だけです。

## 2. 無料／有料の範囲（提案）

| | 無料 | プレミアム（世帯） |
|---|---|---|
| 在庫・買い物・いつものリスト・写真・取り消し・書き出し | ○ | ○ |
| 家族共有の人数 | **2人**（本人の追加端末は数えない） | **6人まで** |
| レシート読み取り（スマホ内で読む・現行方式） | ○ 回数制限なし | ○ 回数制限なし |
| レシート読み取り（サーバーで読む・**未実装**） | お試し 月3枚 | 月30枚 |
| 自動バックアップ・長期の変更履歴（**未実装**） | — | ○（作ってから販売） |
| 価格 | 0円 | **月額398円** または **年額3,980円**（2か月分お得） |

### この線引きの理由
- **スマホ内のレシート読み取りは無料・回数無制限**です。
  - 読み取りは利用者のスマホ内で行うため、運営側の費用は0円です。
  - 回数を制限しても運営の節約にならず、無料版が使いにくくなるだけです。
  - 端末内の処理は改ざんできるため、制限しても守らせられません。
- **上限を付けるのはサーバーでの読み取りだけ**です。
  - 今回の評価（`docs/atokore-receipt-eval-v38.md`）では、スマホ内の読み取りは半角カナの精度が低いとわかりました。
  - 精度を上げるにはサーバーでの読み取りが必要になる見込みです。これは1枚ごとに費用がかかります。
  - そのため「月3枚のお試し／月30枚」の上限を、サーバーで数えます。
- **共有人数**：夫婦2人は無料で使えるようにします。祖父母や保育者を加える世帯向けに、有料で6人まで増やせます。
- **価格**：月額398円は、世帯で使う家計・買い物アプリとして手に取りやすい価格帯を想定しています。年額はその10か月分です。
  - **販売前に再確認が必要**：競合アプリの価格と、利用者への聞き取り。

## 3. 数え方（サーバーで実装・テスト済み）
- **1回の操作は1回だけ数えます**：利用1回ごとに、端末で作るイベントキー（例：レシートの読み取りID）を付けます。
  - サーバーは「世帯・機能・キー」の組を重複不可にします。
  - 再送・連打・応答が届かず再試行した場合・家族の別の端末が同じキーを送った場合も、1回として数えます。
- **同時の利用で上限を超えません**：数える処理は世帯ごとに1件ずつ順番に行います。
  - 残り1回のときに2台が同時に使っても、通るのは1台だけです。
- **失敗した読み取りの扱い**：
  - サーバー側の失敗（読み取りサービスの障害・時間切れ・文字が1つも取れない）は、サーバーが1時間以内に返却します。返却した分は数えません。
    - 返却できるのはサーバーだけです。端末からは返却できないので、成功した読み取りを「失敗」と偽って戻すことはできません。
  - 読み取りが成功した後に、利用者が登録をやめた場合は数えます。費用はすでにかかっているためです。
  - 返却した読み取りを同じキーで再送しても、再度は数えません。もう一度読み取るときは新しいキーを使います。
- **月の区切り**：日本時間の暦月です。前月までの記録は消さずに残し、当月分だけを数えます。
- **他の世帯の利用回数は見えず、使えません**：同じキーでも、世帯が違えば別の利用です。

## 4. 解約・期限切れ（実装・テスト済み）
- **解約**：支払い済みの期間の終わりまでプレミアムのままです。
- **期限切れ・返金**：無料に戻ります。データとメンバーには一切手を付けません。
  - 6人で使っていた世帯が無料に戻っても、誰も外されません。全員が在庫を読み書きできます。
  - 断るのは、無料の人数（2人）を超える新しい招待だけです。
  - 利用回数の記録は残ります。当月はすでに上限を超えている場合、サーバーでの読み取りは来月まで使えません。
- 支払いイベントがなくても、期限の日時を過ぎれば自動で無料扱いになります。

## 5. 将来の支払い接続（準備済みの部分）
- **契約の記録**：世帯ごとの契約（`contracts`）と、受け取った支払いイベント（`contract_events`）をサーバーの表に記録します。
- **イベントの適用**：`apply_contract_event` が、支払いサービスからの通知を反映します。
  - 同じイベントは1回だけ適用します。
  - 古いイベントが遅れて届いても、状態を巻き戻しません。
  - 有効な契約がある世帯に、別の契約を重ねて受け付けません。
  - サーバー（サービスロール）からしか呼べません。
- **今後の実装**：支払いサービスを決めてから、通知を受け取るサーバー関数を作ります。
- **支払いサービスの候補**：
  - iPhoneのアプリとして配布する場合は、App Store のアプリ内課金がほぼ必須です。手数料は小規模事業者向けプログラムで15%です（**要再確認**）。
  - ウェブ（PWA）で販売する場合は Stripe などを使います。国内カードの手数料は3.6%程度です（**要再確認**）。

## 6. 運用費用
- **現在**：0円です。試用版はGitHub Pagesで配信しており、家族共有は利用者がSupabaseの設定を入れるまで動きません。
- **家族共有を試験で動かす場合**：Supabase の無料プランを使います。
  - 無料枠：DB 500MB・月間利用者5万人・ファイル1GB・転送量5GB/月。
  - 注意点：
    - 7日間使われないと一時停止します。
    - 自動バックアップはありません。
    - 標準のメール送信は1時間に2通までなので、ログイン用に外部のメール送信サービスを設定する必要があります。
- **費用が発生し始める条件**：
  - **Supabase Pro**：月25ドル。必要になるのは、無料枠を超えたとき、一時停止を避けたいとき、自動バックアップが必要なとき。
    - 年額3,980円の世帯がおよそ12世帯あれば、この費用をまかなえます（手数料差し引き後の概算）。
  - **メール送信**：外部サービスの無料枠（数千通/月程度）を超えた場合。
  - **サーバーでのレシート読み取り（未実装）**：読み取りサービスごとに1枚単位の料金がかかります。
    - 例：Google Cloud Vision は月1,000枚まで無料、以降は1,000枚あたり約1.5ドル（**公開価格・要再確認**）。
    - 月30枚×1,000世帯の場合、月40〜50ドル程度です。
- **わからない費用**：
  - サーバー読み取りの方式と実際の精度。日本語のレシートで、読み取りサービスを比べて評価する必要があります。
  - 写真共有を始めた場合の容量と転送量（v37では写真は共有していません）。
  - App Store に出す場合の開発者登録費（年額）。
  - 問い合わせ対応の手間。

## 8. 続けて使ってもらえているかの指標（外部の解析サービスを使わない案）
- **端末内だけで記録します**（送信しません）：
  - 初回に登録した商品数
  - 7日後・30日後にも在庫を更新したか
  - 1週間あたりの更新回数
  - レシート登録で直した行の割合
  - 家族共有の参加数
- **集計の方法**：利用者が「利用状況を書き出す」で手元に保存し、任意で送ってもらう形にします。自動送信はしません。
- **家族共有を使っている世帯の場合**：
  - サーバーの記録（操作数・最終更新日）から、世帯ごとの継続状況がわかります。
  - 個人を特定する情報は集計に使いません。
