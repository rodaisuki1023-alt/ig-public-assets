# 試用版 v36: 一括追加後に商品が見えない不具合の修正と、追加予定の確認画面

## 利用者の報告
任意の3商品を追加予定に入れ、「まとめてストックに追加」を押したが、ストックに反映されなかった。
報告の画像で確認できたのは「Rico おしりふき」だけ。残り2商品、操作順、直前の画面状態、エラー表示の有無は確定していない。

## 再現と原因（合成データ、ソース `1cc788b`、Chromium）
- **A 保存失敗**：起きていない。保存済みJSON、メモリ上の`items`、再読み込み後のどれにも3商品とも入っていた。書き込み例外の場合は、追加予定とデータが保たれる設計だった。
- **B 表示条件**：再現した。主な原因。一括追加後のストック画面に、前回のカテゴリー・ベビーの種類・検索語が残っていた。
  - 離乳食／食料品／検索語「卵」の状態：3商品中0件表示
  - ベビー＞おむつの状態：3商品中1件表示
  - 表示条件のリセットは、離乳食を含む一括追加のときにしか動いていなかった。
  - ストック画面を離乳食で開いたまま「＋追加」を押すと、追加画面は離乳食で開く。そこでベビーに切り替えて3商品を選ぶと、保存後のストックは離乳食のまま3商品とも見えない。自然な操作で起こり得る。
- **C 保存後の例外**：潜在的な不具合。保存後の描画で例外が起きると「保存できませんでした。内容を残している」と表示されていた。実際には保存済みで、追加予定も消えていた。通常の操作ではこの例外は確認できなかった。
- **配信**：公開前の配信ファイルは、`1cc788b`の隔離ビルドと41/41ファイルが一致した。サーバー側の版の食い違いはない。端末に残る古いService Workerは確認できない。

## 修正
- **保存後の表示**：保存が確定してから、追加した商品が見える状態にする。表示条件は保存前には変えない。
  - カテゴリーは追加した商品のもの（複数カテゴリーにまたがる場合は「すべて」）にする。
  - 種類・月齢・シリーズ・検索語を解除し、追加した商品を枠で示してスクロールする。
  - 「いつものリスト → ストックに追加」にも同じ処理を入れた。
- **保存と描画の分離**：保存は書き込み後に読み戻して確認する。
  - 失敗したら追加予定と確認画面を残し、再試行できる。
  - 保存後の描画で失敗した場合は「保存しました（もう一度追加する必要はありません）」と表示する。
- **商品選択中**：「追加した商品を確認する」と「追加予定 3商品・合計3点」のコンパクトなバーだけを表示する。0件のときは表示しない。
- **確認画面**：商品名、メーカー・カテゴリー・単位、「登録済みの在庫に合算：2袋 → 3袋」か「新しい商品として登録」か、数量の＋／−（−は1で止まる）、削除、保存先の表示と切り替え。
  - 最終ボタン（「まとめてストックに追加」「まとめて買い物リストに追加」「選んだ商品をいつものリストに追加」）だけが保存する。
  - 「商品選びに戻る」で、検索語と選択条件をそのまま残す。全部取り消しは確認してから取り消す。
- **いつものリストの商品選択**：確認画面を確認の代わりにし、ダイアログを重ねて出さない。
- **連打対策**：最終ボタンの連打で、同じ位置へのタップを400ms無視する（保存後に開いたページにいる間だけ）。
- **キャッシュ**：`quick-add.js?v=36`、`baby-flow-v17.js?v=36`、`batch-review-v36.css?v=36`、Service Worker `atokore-pwa-v36`。
- **変更していないもの**：保存キー、データ形式、写真DB、商品ID・数量、XSS対策、通常版との保存領域・SWの分離。家族同期は無効のまま。
